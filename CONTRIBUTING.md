# Contributing to awesome_c_elegans

Thank you for helping keep this literature tracker accurate and useful.

## Inclusion criteria

A paper belongs in this list if **either**:

1. it is directly related to *C. elegans* embryogenesis — measurement/tracking, developmental dynamics, morphology & mechanics, molecular regulation, perturbation experiments, or fate/lineage biology; **or**
2. it has clear methodological transfer value to at least one tracked category C0–C9 (e.g. graph neural dynamics, neural ODE/SDE, physics-informed ML, single-cell/developmental foundation models), even if the system is not *C. elegans*.

We do **not** include pure *C. elegans* neuroscience or purely clinical work with no embryogenesis connection. Methods-transfer (C7) entries are soft-capped at 30% T3-transfer share.

## The one rule: never edit rendered files

`README.md`, `categories/*.md` and `digest/*.md` are **rendered artifacts**. All changes go through:

- `data/papers.json` — the single source of truth for entries, or
- `config/taxonomy.yaml` / `config/queries.yaml` — classification taxonomy and search queries.

After changing either, run:

```bash
pip install -r requirements.txt
python3 scripts/render.py
python3 scripts/validate.py
```

`validate.py` must exit 0 (it includes a render-consistency check, also enforced by CI).

## Suggesting a paper

- **Preferred**: open an issue with the *Suggest a paper* template (DOI/link, suggested category, rationale). Suggested entries go through the same audit pipeline as automated ones.
- **Manual add by a maintainer**: `python3 scripts/classify.py --add <DOI>` fetches metadata, classifies, and stages the entry for human confirmation before it lands in `papers.json`.

## Pull requests

- Automated weekly/monthly PRs are generated by GitHub Actions and labeled `literature-update, automated`; they must be reviewed before merge.
- Human PRs: use the PR template — list added entries, classification rationale, evidence-level confirmation, and whether the taxonomy changes.
- **Taxonomy or query changes** (`config/*.yaml`) must explain their motivation in the PR description, because they alter future automated classifications.
- `main` is protected: all changes — human or automated — land via reviewed PRs only.

## Evidence labels are mandatory

Every entry carries an `evidence` field: `peer-reviewed`, `preprint`, or `emerging-evidence`. Preprints and emerging evidence are always displayed with their status; emerging-evidence entries additionally render with a ⚠️ warning prefix.
